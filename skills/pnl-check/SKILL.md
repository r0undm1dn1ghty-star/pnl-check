# P&L Check

Проверка цифр для управленческого решения: факты→сверка→бриф. Open-source протокол для агентов, собственников и финансовых руководителей российских компаний.

## When to Use

Используй, когда компания/собственник/финдиректор хочет принять управленческое решение (цены, ФОТ, направление, инвестиция), но нет уверенности, что текущие цифры это поддерживают. P&L Check проверяет, какие цифры подтверждены, где прибыль расходится с деньгами и чего не хватает для безопасного решения.

Триггеры (маркеры запроса):
- «проверь цифры»
- «можно ли принимать решение»
- «сверка прибыли»
- «управленческая отчётность»

Не использовать для: налогового аудита, бухучёта без управленческих решений, налоговых/трудовых/юридических советов, прогноза банкротства, поиска «лишних расходов» по шаблону, замены CFO/бухгалтера/юриста.

## Procedure (3 шага)

### Шаг 1 — Собрать факты
Зафиксируй: юридическое лицо, период, источники, периметр, единицы измерения, пробелы в данных.
**Результат:** Карточка данных + список недостающих документов.

### Шаг 2 — Сверить прибыль и деньги
Сопоставь P&L, остатки, движение денег, дебиторку, кредиторку, долг, разовые статьи.
**Результат:** объяснённые и необъяснённые расхождения.

### Шаг 3 — Подготовить решение
Отдели факт от расчёта, гипотезы и догадки. Сформулируй вопросы и безопасные проверки.
Обязательные поля брифа:
- **Уверенность в выводе:** `high` (P&L и кэш сверены из первоисточников) / `medium` (официальная отчётность без полного разбора примечаний) / `low` (сниппеты СМИ).
- **Adversarial self-check:** «Какой вывод был бы принят без сверки и чем это грозило» + «Какая строка может быть не тем, чем кажется» (GMV vs выручка, FCF с субсидиями, прибыль с разовыми статьями, EBITDA vs прибыль).
**Результат:** Бриф для решения без ложной уверенности.

## Стоп-правила (НЕ нарушать)

1. Не угадывай данные. Нет данных → скажи «нет данных».
2. Не давай налоговых/трудовых/юридических советов. Эскалируй специалисту.
3. Не советуй увольнять, закрывать, дробить, скрывать.
4. Не считай 100 карточек «нормой по отрасли».
5. Не обещай экономию/рост прибыли.
6. Каждый вывод — из источника (строка, формула, мост, вопрос).

## Вход

- `templates/context_questionnaire.md` — опросник компании.
- `templates/pnl_structure.csv` — структура P&L.
- Исходные документы и выгрузки (не только итоговые показатели).

## Выход

- Карточка данных (что подтверждено, что нет).
- Список расхождений (объяснённые/необъяснённые).
- Бриф для решения (факт vs догадка, вопросы, безопасные проверки).
- Если данных мало — `templates/data_gap_report.md` (список недостающего), а не выводы.

## Reference Files

- `SAFETY_RAILS.md` — стоп-правила.
- `DATA_EVIDENCE_STANDARD.md` — стандарт доказательств (уровни).
- `templates/` — опросник, структура P&L, шаблоны результатов.
- `integrations/` — адаптеры (Claude Code, MCP, ChatGPT).
